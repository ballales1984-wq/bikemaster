# Piano: Fix OAuth flow + Route + POI schemas

## Problema principale
Dopo login Google con profilo completo, l'utente rimane sulla schermata di login vuota. Causa: il token viene perso durante il flusso OAuth a causa di logica di fallback scorretta nel catch block.

## Step 1 — Ripristina logica OAuth (P0)
**File:** `frontend/src/main.ts`
- Ripristinare `profileComplete = false` nel catch block (riga 49)
- Aggiungere `console.warn("[OAuth] profile check failed:", err)` per debugging

**File:** `frontend/src/router/index.ts`
- Ripristinare `return false` nel catch block di `checkProfileComplete` (riga 183)
- Ripristinare `next("/athlete")` nel catch block del guard (riga 214) invece di `next("/rides")`
- Aggiungi logging per tracciare `hasToken`, `justLoggedIn`, e risultato profile check

**Verifica:** Testare OAuth flow con profilo completo e incompleto.

## Step 2 — Rimuovi route `/map` orfana (P1)
**File:** `frontend/src/router/index.ts`
- Rimuovere la route `/map` che importa `RideMapPanel.vue` (righe 56-61)

## Step 3 — Aggiungi endpoint POI mancanti (P0)
**File:** `bike_analyzer/backend/api/routes.py`
- Aggiungere `POST /pois` con response_model `POIResponse`
- Aggiungere `GET /pois/{poi_id}` con response_model `POIResponse`
- Usare `POIRepository` per create/get_by_id
- Proteggere con `get_current_user`

## Step 4 — Fix POIResponse schema (P2)
**File:** `bike_analyzer/backend/api/schemas.py`
- Aggiungere `tenant_id: int | None = None` a `POIResponse`
- Verificare se `photos`, `video_url` devono essere nascosti nella response (al momento sono ereditati da `POICreate`)

1 → 2 → 3 → 4

- Il problema OAuth è il blocker principale: senza la diagnostica del token è impossibile capire se si perde prima o dopo il profile check
