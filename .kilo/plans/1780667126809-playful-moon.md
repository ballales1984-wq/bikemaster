# Piano Controllo Totale Applicazione BikeMaster

## Obiettivo
Eseguire un controllo completo dell'applicazione BikeMaster per verificare qualità, sicurezza, performance e completezza.

## 1. Analisi Struttura Codice

### 1.1 Architettura
- **Entry Point**: `main.py` - avvia FastAPI o CLI
- **API Routes**: `bike_analyzer/backend/api/routes.py` (402 linee, 30+ endpoint)
- **Models**: `bike_analyzer/backend/models/models.py` (Ride, GPSPoint, Segment, AthleteProfile)
- **Database**: `bike_analyzer/backend/db/database.py` (SQLite semplice, senza SQLAlchemy)
- **Analytics**: modulo separato per calorie, fatigue, performance, benchmark, AI coach
- **Ingestion**: parser GPX/FIT
- **Maps**: Folium per mappe, supporto Google Maps statiche

### 1.2 Stack Tecnologico
- Backend: FastAPI, Python 3.11+
- Database: SQLite (PostgreSQL-ready indicato ma non implementato)
- Maps: Folium/Leaflet
- Analytics: NumPy, Pandas, Matplotlib
- Parsers: gpxpy, fitparse

## 2. Controllo Qualità Codice

### 2.1 Problemi Identificati

#### Importazioni duplicate (routes.py)
```python
from ..db.database import save_ride, get_ride, get_all_rides, delete_ride
# ... e poi di nuovo:
from ..db.database import get_ride as _get_ride
```
Molti import sono locali all'interno delle funzioni (lazy imports), peggiorando leggibilità.

#### Database - Sicurezza
- **SQLite diretto**: Nessuna validazione input, vulnerabilità SQL injection potenziale
- **Mancanza SQLAlchemy**: Il requirements.txt include sqlalchemy ma non è usato

#### AI Coach - Sicurezza
- **GROQ_API_KEY hardcodato in .env**: Rischio esposizione credenziali
- **Modello LLM hardcodato**: `llama-3.3-70b-versatile` non configurabile

#### Static files path issue (app_factory.py)
- STATIC_DIR punta a `backend/static` ma potrebbe non esistere in tutti gli ambienti

## 7. Analisi Dettagliata Calcoli e Numeri

### 7.1 Formula Calorie (calories.py)

**MET Method** (linea 6-9):
- Speed < 16 km/h → MET 4.0
- Speed 16-19 km/h → MET 6.0
- Speed 19-22 km/h → MET 8.0
- Speed >= 22 km/h → MET 10 + (speed - 22) * 0.5

Formula: `calories = MET * weight_kg * duration_hours`

**Physics Method** (linea 11-21):
- Costanti: g=9.81, crr=0.005, rho=1.225, cdA=0.4, eff=0.25, J_PER_CAL=4184
- Rolling resistance = crr * weight * g
- Air resistance = 0.5 * rho * cdA * v²
- Gravity power = weight * (elevation/distance) * g
- Power tocalories: energy / (efficienza * J_PER_CAL)

### 7.2 Formula Fatigue Score (fatigue.py)

**Peso fattori**:
- Duration: 30% (max 3 punti a 2 ore)
- Intensity: 30% (da freq cardiaca)
- Speed: 20% (max 2 punti a 25 km/h)
- Elevation: 10% (max 1 punto ogni 20m/km)
- Weight: 10% (rapporto peso/70kg)

Formula: `fatigue = min((dur + int + spd + elev + wgt) * 3, 10)`

**Recovery Hours**:
- Score ≤ 3.0 → 8 ore
- Score ≤ 5.0 → 16 ore
- Score ≤ 7.0 → 24 ore
- Score > 7.0 → 48 ore

### 7.3 Performance Score (performance.py)

**Pesi**:
- Speed: 40% (max 30 km/h)
- Duration: 40% (max 2 ore)
- Elevation: 20% (max 500m)
- Formula: `score = (speed*0.4 + duration*0.4 + elevation*0.2) * 10`

### 7.4 Benchmark Percentile (benchmark.py)

Percentili per livello:
- Beginner: 0-100 km, 0-20 km/h
- Amateur: 100-500 km, 20-25 km/h
- Intermediate: 500-1500 km, 25-28 km/h
- Advanced: 1500-3000 km, 28-32 km/h
- Elite: 3000+ km, 32+ km/h

### 7.5 Rangepaia GPS (processing.py)

- Pause threshold: 1.5 km/h
- Pause min duration: 3 minuti
- Accel threshold: > 2 km/h/s
- Max speed outlier filter: 120 km/h

### 7.6 Limiti Input (schemas.py)

- Weight: 20-300 kg
- Age: 10-100 anni
- Heart rate: 30-220 bpm
- Elevation gain: ≥ 0
- Duration/distance: ≥ 0
